# 기획표 사용자 가이드

사용자가 준비하는 것은 **기획표 한 개와 그 표에 적은 사진·영상**입니다. 사진인지 영상인지, 타임라인 시작 시간이 몇 초인지, 음량이 몇 dB인지 직접 계산할 필요가 없습니다.

실행은 [Mac·VS Code 가이드](MAC.md)를 기본으로 권장합니다. 설치 없이 짧게 시험하려면 [Colab 가이드](02_BEGINNER_COLAB.md)를 사용하세요.

## 1. 입력 폴더

```text
my-video/
├─ timeline.xlsx          # 또는 timeline.csv
└─ Media/
   ├─ intro.mov
   ├─ photo.jpg
   └─ outro.mp4
```

- 기획표는 `.xlsx` 또는 UTF-8 `.csv`를 사용합니다.
- Numbers 사용자는 `파일 > 다음으로 내보내기 > Excel`로 `.xlsx`를 만듭니다.
- `.numbers`, `.xls`, `.xlsm`은 직접 입력하지 않습니다.
- 사진과 영상은 섞어도 됩니다.
- 영상은 `.mp4`, `.mov`, `.m4v`, `.avi`, `.mkv`, `.webm`, 사진은 `.jpg`, `.jpeg`, `.png`, `.tif`, `.tiff`, `.heic`, `.webp`, `.bmp`를 지원합니다. Final Cut 호환이 불확실하면 영상은 MOV 또는 MP4로 변환하세요.
- 기획표의 파일명과 `Media`의 실제 파일명이 같아야 합니다.
- `timeline.xlsx`와 `timeline.csv`가 둘 다 있으면 하나를 지우거나 `--timeline`으로 사용할 파일을 지정합니다.

`.xlsx`와 `.csv` 사이에는 자동 우선순위가 없습니다. `--timeline`을 지정하지 않으면 먼저 표준 이름 `timeline.xlsx`/`timeline.csv`를 찾고, 두 파일이 모두 없을 때만 프로젝트 폴더의 다른 `.xlsx`/`.csv` 한 개를 사용할 수 있습니다. 어느 단계든 후보가 여러 개면 최신 파일을 추측하지 않고 중단합니다.

처음에는 [Excel·Numbers용 기본 양식](../templates/simple_timeline.xlsx)을 복사해 사용하세요.

GitHub에서 행을 바로 확인하려면 [기본 6열 CSV 예제](../examples/quick_start/timeline.csv)와 [세로·가로 선택 열 CSV 예제](../examples/multi_format/timeline.csv)를 참고하세요. 선택 열을 Excel에서 바로 쓰려면 [세로·가로 Excel 양식](../templates/multi_format_timeline.xlsx)을 복사합니다.

## 2. 기본 6열

| 열 | 필수 | 입력 방법 | 빈칸이면 |
|---|:---:|---|---|
| `파일` | O | `intro.mov`처럼 확장자 포함 | 오류 |
| `영상 원본 시작` | 영상 선택 | 사용할 영상 구간의 시작 | 시작·끝 모두 비면 전체 사용 |
| `영상 원본 끝` | 영상 선택 | 사용할 영상 구간의 끝 | 시작·끝 모두 비면 전체 사용 |
| `사진 표시 시간(초)` | 사진 선택 | `3`, `2.5`처럼 초 단위 | 3초 |
| `화면 자막` | 선택 | 장면 동안 보일 문장 | 자막 없음 |
| `소리` | 영상 선택 | `사용` 또는 `끄기` | 원본 소리 사용 |

```csv
파일,영상 원본 시작,영상 원본 끝,사진 표시 시간(초),화면 자막,소리
intro.mov,00:00:01.000,00:00:04.000,,처음 Mac을 켰다,사용
photo.jpg,,,3,주말에는 Apple Store로,
outro.mp4,,,,6주간 모니터링 예정,끄기
```

기획표에 보이는 행 순서가 완성 영상의 장면 순서입니다.

## 3. 영상 행 작성

### 영상 전체 사용

원본 시작과 끝을 모두 비웁니다.

| 파일 | 영상 원본 시작 | 영상 원본 끝 | 사진 표시 시간(초) |
|---|---|---|---|
| `office.mp4` |  |  |  |

### 영상 일부 사용

시작과 끝을 모두 입력합니다.

| 파일 | 영상 원본 시작 | 영상 원본 끝 | 결과 길이 |
|---|---|---|---:|
| `cafe.mov` | `00:00:12.000` | `00:00:16.000` | 4초 |

- 시작만 또는 끝만 입력하면 오류입니다.
- 끝은 시작보다 뒤여야 합니다.
- 끝 시간이 실제 영상 길이를 넘으면 오류입니다.
- 영상 행의 `사진 표시 시간(초)`는 비웁니다.

## 4. 사진 행 작성

사진에는 원본 시작·끝이 없습니다.

| 파일 | 영상 원본 시작 | 영상 원본 끝 | 사진 표시 시간(초) |
|---|---|---|---:|
| `drawing.png` |  |  | `3` |

- `3`은 3초, `2.5`는 2.5초입니다.
- 비우면 3초로 처리합니다.
- 사진의 `소리`는 비워 둡니다.

사진은 프로젝트 규격에 맞는 편집 캐시로 만들어집니다. 생성된 `.build_media` 폴더를 지우거나 XML과 분리하지 마세요.

## 5. 시간 입력

권장 형식은 `시:분:초.밀리초`입니다.

```text
00:00:12.000   12초
00:01:02.500   1분 2.5초
```

초 단위 숫자 `12`, `12.5`도 사용할 수 있습니다. 프레임률에 정확히 맞지 않는 시간은 가까운 프로젝트 프레임으로 조금 보정되고 검사 결과에 표시됩니다.

## 6. 파일명 규칙

```text
기획표: intro.mov    Media: intro.mov    올바름
기획표: intro.mov    Media: Intro.MOV    서로 다름
```

- 폴더 경로를 쓰지 말고 파일명만 씁니다.
- 확장자를 반드시 씁니다.
- 같은 이름의 미디어를 여러 개 두지 않습니다.
- 파일명을 바꿨다면 기획표도 함께 바꿉니다.
- 셀 앞뒤의 불필요한 공백을 지웁니다.

## 7. 화면 방향 선택

화면 방향은 기획표의 매 행에 적지 않고 실행할 때 한 번 선택합니다.

| 선택 | 해상도·비율 | 용도 예시 |
|---|---|---|
| `portrait` | 1080×1920, 9:16 | Reels·Shorts |
| `landscape` | 1920×1080, 16:9 | 일반 YouTube |
| `both` | 두 프로젝트 모두 | 같은 컷과 자막을 두 규격으로 제작 |

```bash
python make_xml.py projects/my-video --layout both
```

`both`는 장면 순서, 사용 구간과 자막 시간이 같은 편집안을 두 화면비로 바꾸는 기능입니다. 세로와 가로에서 장면 순서·영상 길이·자막 문구까지 다르다면 기획표를 두 프로젝트로 분리하세요.

## 8. 화면 맞춤 선택 열

원본과 프로젝트 비율이 다를 때 필요한 경우에만 열을 추가합니다.

| 선택 열 | 입력값 | 의미 |
|---|---|---|
| `화면 맞춤` | `전체 보이기` 또는 `화면 채우기` | 두 방향 공통 |
| `세로 화면 맞춤` | `전체 보이기` 또는 `화면 채우기` | 세로 결과만 별도 지정 |
| `가로 화면 맞춤` | `전체 보이기` 또는 `화면 채우기` | 가로 결과만 별도 지정 |

적용 우선순위는 다음과 같습니다.

1. 해당 방향의 `세로 화면 맞춤` 또는 `가로 화면 맞춤`
2. 공통 `화면 맞춤`
3. 도구의 안전한 기본값

### 전체 보이기

원본 전체가 보입니다. 가로 영상을 세로 프로젝트에 넣거나 그 반대라면 여백이 생길 수 있습니다.

### 화면 채우기

프레임을 꽉 채웁니다. 대신 좌우 또는 위아래가 잘릴 수 있습니다. 사람 얼굴, 제품, 화면 글씨가 가장자리에 있다면 주의하세요.

예:

| 파일 | 화면 맞춤 | 세로 화면 맞춤 | 가로 화면 맞춤 |
|---|---|---|---|
| `wide_interview.mov` | `전체 보이기` | `화면 채우기` | `전체 보이기` |
| `portrait_photo.jpg` | `전체 보이기` |  | `전체 보이기` |

첫 장면은 세로 결과에서만 화면을 채우고, 가로 결과에서는 원본 전체를 보존합니다.

## 9. 생성 전 검사와 미리보기

먼저 기획표와 미디어 구조를 검사합니다.

```bash
python make_xml.py projects/my-video --layout both --validate-only
```

오류가 없다면 방향별 미리보기 HTML을 만듭니다.

```bash
python make_xml.py projects/my-video --layout both --preview-only
```

명령이 안내한 HTML을 브라우저로 엽니다. 기본 경로는 `projects/my-video/Generated/preview/index.html`입니다. 다음을 확인합니다.

- 원본이 가로·세로·정사각형 중 무엇인지
- 각 결과에 `전체 보이기`와 `화면 채우기` 중 무엇이 적용되는지
- 크롭 또는 여백이 예상되는 장면
- 자막이 길어 과도하게 줄바꿈될 수 있는 장면
- 자막이 화면 가장자리나 플랫폼 UI 영역과 가까운지
- 생성할 해상도와 FPS

`--validate-only`는 입력 오류를 찾는 단계이고, `--preview-only`는 배치를 눈으로 확인하는 단계입니다. 미리보기는 대표 프레임과 예상 배치를 사용하므로 실제 폰트 렌더링, 얼굴의 정확한 위치와 플랫폼 버튼 겹침은 Final Cut에서 최종 확인합니다.

## 10. 화면 자막

기본 `화면 자막`은 장면 시작부터 끝까지 보이는 **Basic Title**로 생성됩니다.

- 일반 영상 내보내기에 함께 표시됩니다.
- Caption 번인 설정이 필요하지 않습니다.
- SRT도 별도로 생성할 수 있습니다.
- 줄바꿈은 셀 안에서 직접 줄을 바꾸거나 `\n`을 사용할 수 있습니다.

세로와 가로는 폭이 다르므로 도구가 방향별 줄바꿈 폭과 위치를 적용합니다. 고정된 픽셀 위치를 그대로 복사하지 않고 화면 비율에 맞춘 안전영역을 사용합니다.

자막이 너무 길면 다음처럼 문장을 줄이는 것이 좋습니다.

```text
수정 전: 서로 다른 Apple 계정에서 작업한 파일을 맥으로 가져와 영상에 넣었습니다
수정 후: 다른 Apple 계정의 작업물을
         Mac으로 가져왔다
```

## 11. 한 장면에서 자막이 여러 번 바뀔 때

기본 `화면 자막`은 장면당 한 개입니다. 한 영상 장면 안에서 자막이 여러 번 바뀐다면 기본 열을 비우고 별도 `subtitles.xlsx` 또는 `subtitles.csv`를 사용합니다.

| 번호 | 시작 | 끝 | 최종 대사 | 장면 의도 |
|---|---|---|---|---|
| S01 | `00:00:00.200` | `00:00:01.800` | 드디어 Mac을 켰다 | 첫 장면 |
| S02 | `00:00:02.000` | `00:00:03.800` | 그런데 생각보다 어렵다 | 첫 장면 후반 |

이 시간은 원본 영상 시간이 아니라 **모든 장면을 이어 붙인 완성 타임라인 시간**입니다. 인라인 `화면 자막`과 별도 자막표를 동시에 사용하지 않습니다.

별도 자막표 선택 규칙도 XLSX를 CSV보다 우선하지 않습니다.

1. `--subtitles 파일명`을 쓰면 지정한 프로젝트 내부 파일을 사용합니다.
2. 생략하면 프로젝트 루트와 `Docs/`의 `subtitles.xlsx`/`subtitles.csv` 중 한 개를 사용합니다.
3. 표준 이름이 없으면 `Docs/`의 유일한 `*대사표*.xlsx` 또는 `*대사표*.csv`를 사용합니다.
4. 같은 단계의 후보가 여러 개면 중단하므로 `--subtitles`로 하나를 지정합니다.
5. 별도 자막이 필요 없으면 `--no-subtitles`로 자동 탐색을 끕니다. 이 옵션은 `--subtitles`와 함께 쓰지 않습니다.

Numbers 자막표도 `.numbers` 원본을 직접 입력하지 않습니다. `파일 > 다음으로 내보내기 > Excel`로 `.xlsx`를 만든 뒤 사용합니다.

## 12. 소리와 dB

초보자 기획표에서는 dB를 계산하지 않습니다.

- `사용`: 영상 원본 소리를 기본 레벨로 포함
- `끄기`: 영상 원본 소리를 제외
- 빈칸: `사용`과 같음

BGM, 페이드, 장면별 음량 dB가 필요할 때만 [고급 입력 형식](INPUT_FORMAT.md)을 사용합니다. 첫 러프컷에서는 소리를 포함할지 여부만 정하고 Final Cut에서 귀로 확인하며 조정하는 편이 안전합니다.

## 13. 결과 읽기

```text
Generated/
├─ preview/index.html
├─ vertical_9x16/
│  ├─ *_with_titles.fcpxml
│  ├─ *_clean.fcpxml
│  ├─ *.srt
│  ├─ build_report.txt
│  └─ .build_media/
└─ horizontal_16x9/
   └─ 같은 종류의 가로 결과
```

- 화면 자막이 입력되어 있으면 `*_with_titles.fcpxml`을 가져옵니다.
- 자막 없는 편집안은 `*_clean.fcpxml`입니다.
- `.srt`는 YouTube 등 플랫폼에 별도 자막으로 올릴 때 사용합니다.
- `build_report.txt`에는 입력, 경고, 해상도와 FPS 확인 결과가 들어 있습니다.
- `preview/index.html`은 브라우저로 여는 검토 파일이며 Final Cut에 가져오지 않습니다.

## 14. Final Cut 가져오기

1. Final Cut Pro에서 테스트 Library와 Event를 엽니다.
2. `File(파일) > Import(가져오기) > XML`을 선택합니다.
3. 원하는 방향 폴더의 `*_with_titles.fcpxml`을 선택합니다.
4. 세로와 가로 결과를 각각 가져옵니다.
5. 장면 순서, 길이, 화면 잘림·여백, 소리와 자막을 확인합니다.
6. 필요한 부분은 Final Cut의 Transform·Spatial Conform·Title 설정으로 조정합니다.
7. 편집을 마친 뒤 `File(파일) > Share(공유)`로 내보냅니다.

XML만 다른 위치로 옮기면 미디어가 오프라인으로 보일 수 있습니다. 프로젝트의 `Media`와 `Generated` 폴더 구조를 함께 유지하세요.

## 15. Excel·CSV가 깨져 보일 때

- 한글이 `???`로 보이면 그 상태로 저장하지 않습니다.
- 가능하면 `.xlsx` 양식을 다시 사용합니다.
- CSV가 필요하면 Excel의 `CSV UTF-8` 또는 Numbers의 UTF-8 옵션으로 다시 내보냅니다.
- CSV를 메모장으로 열었다 닫으며 인코딩을 바꾸지 않습니다.

## 16. Colab을 사용해도 되는 경우

Colab은 Python 설치 없이 시험할 때 편리하지만 선택한 기획표와 미디어가 Google의 임시 실행 환경에 업로드됩니다.

다음 자료는 Mac 로컬에서 처리하세요.

- 회사 기밀·NDA·공개 전 원본
- 민감한 얼굴·음성·주소·위치 정보
- 수 GB 이상의 4K·ProRes 영상
- 여러 번 반복 생성할 프로젝트

## 문제가 생기면

[문제 해결](TROUBLESHOOTING.md)에서 오류 문구를 찾고, 해결되지 않으면 실행 명령·오류 전문·기획표의 해당 행·`build_report.txt`를 함께 준비하세요.
