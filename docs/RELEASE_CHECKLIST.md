## 자동 검증

```bash
python -m unittest discover -s tests -v
```

기획표 행/시간/파일명, CSV·XLSX 예시 일치, 사진 캐시 충돌, 반복 사진,
타이틀/시간/상대 경로, 실패 후 다운로드 차단, 업로드 완료, 이전 결과 혼입 방지,

노트북 셀의 업로드·다운로드를 모의 실행하는 테스트는 실제 Colab 브라우저 시험이 아닙니다.

## 수동 공개 게이트

- [ ] 실제 Colab 새 런타임에서 1~5번 셀, CSV와 XLSX 각각 성공.
- [ ] 기획표 업로드 취소/미디어 누락 시 변환과 다운로드 중단.
- [ ] 성공 후 실패한 변환에서 이전 결과 ZIP이 내려받아지지 않는지 확인.
- [ ] both 결과를 Mac의 새 폴더에 압축 해제.
- [ ] Apple FCPXML 1.14 전체 DTD 검증. 내부 부분집합 검사는 이 항목의 통과가 아닙니다.
- [ ] Final Cut Pro 12.0 이상에서 세로·가로 XML 각각 가져오기.
- [ ] 영상 구간, 총 길이, 소리, Basic Title 위치/글꼴/줄바꿈 확인.
- [ ] 같은 사진을 5초와 1초로 재사용한 장면 확인.
- [ ] 한글/공백 파일명, 실제 세로 촬영 영상, HEIC, 회전/HDR/VFR는 사용하는 원본으로 확인.
- [ ] 블로그 가이드의 촬영 자리를 실제 스크린샷으로 채우기.

자동 테스트만으로 수동 확인란을 채우지 않습니다.

## 배포 순서

1. PR의 CI와 위 수동 확인을 완료합니다.
2. 코어 커밋을 확정하고 노트북 CORE_REV를 그 40자리 SHA로 고정합니다.
3. 노트북을 별도 커밋합니다. README의 Colab 버튼도 노트북 커밋 또는 고정 릴리스 태그를 가리키게 합니다.
4. 검증한 변경을 main에 병합합니다.
5. v0.6.2 태그/릴리스를 만들고 블로그를 공개합니다. 후보 상태에서 정식 릴리스 태그를 만들지 않습니다.

노트북에 자기 자신을 포함한 커밋 SHA를 기록하면 순환 참조가 됩니다.
코어 코드 커밋 → 해당 SHA를 참조하는 노트북 커밋 순서로 분리합니다.
기존 태그/커밋은 이동하거나 덮어쓰지 않습니다.
